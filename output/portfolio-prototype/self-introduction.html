01 / 지원 동기

게임의 동작과 상태를 함께 다루는 개발자

제가 게임 클라이언트 개발을 선택한 이유는 코드로 만든 규칙이 플레이어의 조작과 화면 반응으로 이어지는 과정에 흥미를 느꼈기 때문입니다. 자료구조 수업에서 연결 리스트의 삽입·삭제·검색을 직접 구현하고, 게임 제작 수업에서 그 논리가 실제 플레이로 이어지는 경험을 하며 진로를 구체화했습니다.

이후 C++·OpenGL 게임의 캐릭터 정보 송수신과 충돌 처리, Unreal Engine의 신체 분리와 차량 탑승, Unity의 턴 진행과 멀티플레이 상태 전환을 경험했습니다. 크로스파이어 라이브 클라이언트 직무에서도 기존 코드의 데이터 흐름과 변경 영향을 먼저 이해하고, 기능 구현과 오류 수정을 함께 수행하는 개발자로 기여하고 싶습니다.

02 / 구현 경험

캐릭터 정보가 다른 화면에 반영되기까지

NGP 프로젝트에서는 팀원이 만든 로컬 장애물 경주 게임을 네트워크 게임으로 확장했습니다. 저는 캐릭터 정보 송수신, 이동과 충돌 처리, 뷰포트 및 캐릭터 초기화 작업을 맡았습니다. 기존 게임 제작과 서버 연결·스레드 구성은 팀원의 작업을 바탕으로 협업했습니다.

캐릭터의 위치·방향·회전·팔다리 움직임 정보를 전달하고, 수신한 다른 플레이어 정보를 화면에 반영하도록 연결했습니다. 충돌은 클라이언트에서 AABB의 겹침을 확인하고, X·Z 중 덜 겹친 축으로 위치를 보정하는 방식으로 처리했습니다. 이 경험을 통해 네트워크 게임에서는 데이터 전송뿐 아니라 수신 이후의 상태 갱신과 화면 반영 경로까지 함께 살펴봐야 한다는 점을 배웠습니다.

03 / 문제 해결

충돌 설정과 이동 기준을 나누어 확인했습니다

졸업작품에서 트럭 짐칸에 탄 플레이어가 튀어 오르는 문제를 겪었습니다. 처음에는 트럭과 플레이어의 충돌을 조정했지만, 이후에는 트럭이 이동할 때 플레이어가 뒤로 밀리는 문제가 남았습니다. 두 현상을 구분해 살펴보며 충돌 설정과 움직이는 바닥을 따라가는 이동 기준을 각각 확인했습니다.

트럭의 적재함을 캐릭터의 이동 Base로 설정하고, 하차할 때는 Base와 관련 상태를 해제하는 방식으로 처리했습니다. 현재 코드에서는 적재함 기준 로컬 좌표로 탑승 위치를 전달하고, 일반 이동으로 돌아갈 때 이동 상태를 다시 맞추는 흐름도 사용합니다. 이 과정에서 한 장면의 증상만 고치는 데서 멈추지 않고 탑승·이동·하차로 이어지는 상태 변화를 함께 점검하는 습관을 갖게 되었습니다.

04 / 협업과 개발 도구

기존 구현 위에서 수정 범위를 분명히 합니다

FlickDom에서는 팀원이 구축한 Host/Client 동기화 기반 위에서 턴 흐름과 멀티플레이 상태 전환, 네트워크 구조 수정, WebGL 빌드·배포를 맡았습니다. 늦게 도착한 정보가 현재 상태를 되돌리지 않도록 라운드·턴 정보를 비교하는 처리와, 이미 획득한 카드 상태를 이전 상태로 덮어쓰지 않도록 검사하는 코드를 추가했습니다.

개발에는 AI와 Unity MCP를 활용했습니다. 도구 사용 자체보다 최종 코드의 상태 전환과 변경 내용을 설명할 수 있는 것이 중요하다고 생각합니다. 팀 프로젝트에서는 담당 범위를 나누고 진행 내용을 공유했으며, 서로 다른 구현을 연결하는 과정에서 발생한 문제를 수정했습니다. 앞으로도 AI를 구현과 탐색에 활용하면서 결과를 확인하고 유지보수하는 책임은 개발자가 맡는다는 기준으로 일하겠습니다.
