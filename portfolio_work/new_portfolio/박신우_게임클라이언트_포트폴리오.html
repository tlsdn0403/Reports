FlickDom Technical Case 01

P2 Flick 예측과 Host 최종 판정

04 / 10

문제와 선택

P2가 디스크를 튕긴 직후 Client 화면에서는 즉시 움직임이 보여야 하지만, 최종 결과는 Host 물리가 결정해야 했습니다. Client가 Host Transform만 기다리면 입력 반응이 늦고, Client 물리를 그대로 믿으면 Host와 결과가 달라집니다.

그래서 Client는 입력 직후 로컬 예측을 시작하고, Host에는 FlickRequest를 보냅니다. Host는 현재 턴, 소유자, 말 ID, impulse 범위를 검증한 뒤 물리를 실행합니다. 움직이는 중에는 Transform Snapshot을 적용하고, 정착 이후 PhysicsSettled Snapshot을 받아 예측을 종료합니다.

Client InputP2가 방향과 힘을 계산하고 즉시 예측 시작
FlickRequestowner, pieceId, direction, power, shotId 전송
Host Physics턴/소유자/힘 범위 검증 후 Rigidbody force 적용
ReconcilePhysicsSettled 최종 Snapshot으로 예측 종료

FlickRequest 전송 전 방향/힘 정규화

public void SubmitFlickRequestToHost(
    FlickDomPlayerId owner, string pieceId,
    Vector3 impulse, uint shotId)
{
    FixedString64Bytes fixedPieceId =
        new FixedString64Bytes(pieceId ?? string.Empty);

    DecomposeFlickImpulse(impulse, out Vector3 dir, out float power);
    NormalizeNetworkFlickCommand(dir, power, out dir, out power);

    writer.WriteValueSafe((int)owner);
    writer.WriteValueSafe(fixedPieceId);
    writer.WriteValueSafe(dir);
    writer.WriteValueSafe(power);
    writer.WriteValueSafe(shotId);
    SendNamedMessage(FlickRequestMessageName, ServerClientId, writer);
}

보드 점령, 카드 판정, 상태 Snapshot

05 / 10

문제

보드 점령, 카드 완료, 점수 증가를 Client가 각각 계산하면 Host와 다른 결과가 나올 수 있습니다. 특히 카드 Stage가 넘어간 직후 이전 Snapshot이 늦게 들어오면 Client 화면이 이전 카드 상태로 되돌아갈 수 있습니다.

해결 방법

Client는 배치 의도만 PlacementRequest로 보내고, Host가 TokenMapManager.TryClaimCell로 점령 가능 여부와 재배치 source를 확정합니다. 이후 BoardState, ScoreState, CardState Snapshot을 전송하고 Client는 stale Snapshot을 거부한 뒤 화면만 갱신합니다.

PlacementClient 클릭은 요청, 확정은 Host
BoardState5x5 owner grid를 Snapshot으로 적용
ScoreState점수와 승리자만 Host가 확정
CardStateStage, seed, claimedCards를 비교

점령/재배치 검증 지점

Infection Technical Case 02

트럭 탑승 중 이동 기준 문제 디버깅

07 / 10

증상

트럭 짐칸에 탑승한 플레이어가 튀거나 뒤로 밀리는 문제가 있었습니다. 처음에는 Mesh 충돌처럼 보였지만, 실제로는 충돌 구조와 이동 기준, 멀티플레이 위치 보정이 함께 얽힌 문제로 보았습니다.

해결 방향

매 프레임 위치를 보정하는 방식은 물리와 네트워크 보정이 다시 충돌할 수 있습니다. 트럭 위에 있을 때는 SetBase(NewBase)로 트럭 바닥을 이동 기준으로 잡고, 점프나 하차 시 SetBase(nullptr)와 상태 초기화를 수행하는 구조로 정리했습니다.

Symptom튀어 오름 / 뒤로 밀림
Separate충돌 문제와 이동 기준 문제 분리
Base트럭 바닥을 이동 기준으로 지정
ExitJump / 하차 시 Base 해제
SetBase(NewBase), SetBase(nullptr), 상태 초기화 코드는 [코드 캡처 필요]. 전후 영상이 있으면 이 페이지의 설득력이 크게 올라갑니다.
