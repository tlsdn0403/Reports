Project 01 · Combat

BoneName 기반
좀비 부위 피격

문제점

총알이 좀비 Mesh가 아니라 Capsule Collision에 먼저 맞아 HitResult의 BoneName이 None으로 들어왔습니다.

개선점

총알과 Capsule의 충돌 채널을 분리해 Mesh에서 피격 판정을 받도록 수정하고, BoneName을 부위 내구도와 연결했습니다.

배운점

게임플레이 버그는 코드만이 아니라 Collision 설정, Asset 구조, Animation 상태까지 함께 추적해야 해결됩니다.

Project 02 · Role

어떠한 역할을 수행했나요?

Host 권위 턴 구조

턴 시작, Flick 요청, 물리 안정화, 점수 계산, 다음 턴 전환이 Host 기준으로만 확정되도록 설계했습니다.

요청 검증

FlickRequest와 PlacementRequest에서 소유자, 턴 상태, 입력 값, 배치 가능 여부를 검증했습니다.

Snapshot 동기화

BoardState, ScoreState, CardState를 Snapshot으로 전달해 클라이언트 화면을 동일하게 맞췄습니다.

Client Prediction

입력 즉시 조작감을 주되, PhysicsSettled 이후 Host 결과로 최종 보정하는 흐름을 적용했습니다.

13
Project 02 · Network

멀티플레이 턴을
어떻게 안정화했나요?

Client Input → Request Validation → Host Simulation → PhysicsSettled → Board / Score / Card Snapshot → Client Correction

클라이언트가 입력을 보냈다고 바로 결과를 확정하지 않고, Host가 검증한 뒤 물리 결과와 보드 점령 상태를 Snapshot으로 내려주는 구조로 정리했습니다.
